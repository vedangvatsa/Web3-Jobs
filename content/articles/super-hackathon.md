## About the Hackathon

The Super Hackathon is a global Web3 event designed to demonstrate the scalability and security of Super Protocol’s cloud under real on-chain load. Participants will migrate existing open-source dApps to opBNB, integrate confidential oracle data feeds, and generate verifiable transactions to stress-test performance. The goal is to showcase how real-world decentralized services can operate efficiently, privately, and transparently at scale.

### About Super Protocol

Super Protocol is a confidential Web3 AI cloud that brings together the power of blockchain and confidential computing. It provides developers with a secure, decentralized environment to deploy applications and AI workloads without relying on centralized providers, ensuring data privacy and verifiable execution.

### About Confidential Oracles

Confidential oracles are a key showcase of Super Protocol’s architecture. Built on Chainlink Data Feeds and executed inside Trusted Execution Environments (TEEs), they keep all data and computations private while remaining verifiable on-chain. Super Protocol achieves the same trust as traditional oracles with far fewer nodes, delivering major improvements in speed and cost efficiency.

## How It Works: Key Requirements

### 1. Choosing a dApp for Migration

The core task is to migrate an existing, eligible dApp to the opBNB network.

-   **Chainlink Requirement:** The original dApp must already use Chainlink Data Feeds in its on-chain logic.
-   **Public and Verified:** The original dApp must be open-source and have been publicly deployed before September 1, 2025, on Ethereum, Polygon, or BNB Chain. Its contracts must be verified on a public block explorer.
-   **Minimal Changes:** The migration should require minimal code changes (no more than 5% of the original codebase).
-   **License:** The project’s license must allow forking and reuse (e.g., MIT, Apache 2.0, GPL-family).

### 2. Deployment and Submission

-   **Timeline:** All projects must be deployed to opBNB between October 13, 2025 (11:00 UTC) and October 31, 2025 (11:00 UTC).
-   **Verification:** Only verified contracts will be accepted for both the original and migrated versions.
-   **Submission:** Projects must be submitted through the official Super Hackathon webpage, using a consistent team wallet for all submissions.

### 3. Confirmation and Scoring

Each submission undergoes an automated confirmation process to check eligibility, code similarity, and Chainlink usage. Points are awarded based on three factors:

1.  **Unique dApp Bonus (100 points):** The first team to submit a specific dApp (based on its original contract address) gets a uniqueness bonus.
2.  **Deployment (100 points):** Each successfully deployed and confirmed contract on opBNB earns the team 100 points.
3.  **Transactions (1-100 points):** The total number of successful transactions generated by the deployed contracts determines an activity score, calculated on a curve.

## Frequently Asked Questions

### Do I need to build a dApp from scratch?
No, the hackathon is focused on migrating existing open-source dApps to opBNB. You can also build from scratch if you prefer, as long as it meets the eligibility criteria.

### How do I migrate dApps and integrate the data feeds?
The process involves deploying the dApp's smart contracts to the opBNB network and updating any frontend configurations. Super Protocol provides detailed guides and confidential oracle examples to assist with integration.

### Is a frontend required?
Frontends are welcome and encouraged for a better user experience, but they are optional. The evaluation and scoring are based solely on the deployed smart contracts and their on-chain activity.

### Which networks are supported for migration?
The original dApp must have been publicly deployed before September 1, 2025, on Ethereum, Polygon, or BNB Chain.

### Can one team submit multiple projects?
Yes, teams may submit multiple unique dApps. However, each submission must have a different original contract address to qualify as unique. Duplicate projects from the same team are not allowed.

### How does scoring work?
Scoring is based on three factors: a 100-point bonus for being the first team to submit a unique dApp, 100 points for each successfully deployed contract on opBNB, and an activity score from 1-100 based on the total number of successful transactions generated.
