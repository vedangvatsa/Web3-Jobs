VeChainThor is scheduled to activate its Interstellar hardfork on Sept. 16 at block height 25,902,540, implementing VeChain Improvement Proposal 255 in a single coordinated upgrade. The hardfork bundles 11 Ethereum improvements to bring the network's virtual machine closer to current Ethereum standards, according to a [Sept. 14 report by CoinTrust](https://www.cointrust.com/market-news/vechain-interstellar-upgrade-set-to-transform-thor-network). No token migration or contract-address change is required.

Interstellar is the third phase of VeChain's Renaissance roadmap. Galactica modernized the network's EVM foundations and fee market, and Hayabusa changed its consensus and economic model. Interstellar now targets compatibility with the wider Ethereum ecosystem, expanding what developers can build and preparing the network for more demanding applications, VeChain said in its [official upgrade overview](https://vechain.org/vechain-renaissance-interstellar-sets-course). VIP-255 moves VeChainThor's execution layer from its current Shanghai-compatible implementation to compatible improvements drawn from Ethereum's Cancun, Prague, and Osaka releases. Adopting them together closes much of the compatibility gap while avoiding several separate consensus-breaking upgrades.

The 11 included proposals add new computation and cryptography primitives. EIP-1153 introduces transient storage through TLOAD and TSTORE instructions, letting contracts hold temporary state that clears after execution for cheaper patterns such as reentrancy guards; on VeChainThor the storage is scoped to an individual clause. EIP-5656 adds MCOPY, a dedicated instruction for copying data between memory locations that simplifies common operations and works better with modern Solidity and Vyper tooling. EIP-6780 restricts when SELFDESTRUCT can delete a contract, and VeChainThor evaluates creation and destruction within the same clause because the network supports multi-clause transactions. EIP-7939 adds the CLZ opcode for counting leading zero bits, useful in math operations, compression, bitmap handling, and zero-knowledge applications.

Two precompiles expand onchain cryptography. EIP-2537 adds native BLS12-381 curve operations used in zero-knowledge systems, signature aggregation, bridges, and interoperability protocols, running far more efficiently as precompiles than as contract bytecode. EIP-7951 adds native verification for the secp256r1 curve, also known as P-256, which underpins passkeys, FIDO2, WebAuthn, Apple Secure Enclave, and Android Keystore, creating a basis for hardware-backed authentication in wallets and applications. EIP-7823 and EIP-7883 bound MODEXP inputs and adjust its gas costs so users pay in line with the actual computation and oversized inputs cannot threaten consensus. EIP-2935 lets contracts read the most recent 8,191 VeChainThor block identifiers through a compatible interface. EIP-7825 caps any single transaction at 16,777,216 gas, and EIP-7934 limits RLP-encoded blocks to 8 MiB to protect propagation, execution, and validation.

The upgrade preserves the architecture that distinguishes VeChainThor from Ethereum. Multi-clause transactions and fee delegation continue unchanged. The dual-token model, the network's block-ID structure, and its precompiled-contract conventions stay in place. Blob-carrying transactions and blob opcodes are not introduced. Historical block queries return VeChainThor block identifiers rather than Ethereum hashes. Developers porting Ethereum contracts still need to review the VeChainThor-specific implementation requirements published with VIP-255. The upgrade matters because of what the EVM represents. VeChain describes the Ethereum Virtual Machine as the most widely adopted smart-contract execution environment in Web3, underpinning development tools, programming languages, libraries, and applications. Staying aligned with its evolving standards lets developers deploy existing applications on VeChainThor, use modern tooling, and build new products without compatibility barriers. Support for newer opcodes and cryptographic precompiles also opens recent compiler targets, established contract libraries, and patterns spanning passkey wallets, account security, bridges, and zero-knowledge systems.

VeChain put VIP-255 to an all-stakeholder vote from Aug. 10 to Aug. 17 through its VeVote platform, open to validators and eligible StarGate NFT holders, with the activation block to be announced after approval and testing. With the vote complete, node operators face a firm deadline: validators, public-node operators, exchanges, custodians, and infrastructure providers must install the compatible Thor client release, version 2.5.0, before the activation block. Nodes that have not upgraded will stop following the canonical chain. VeChain said release notes and upgrade instructions would be provided to operators ahead of activation.

Exchanges are expected to restrict transfers around the event under standard network-upgrade procedures. CoinTrust reported that major platforms including Binance are expected to temporarily suspend VET deposits and withdrawals during the transition. Holders who need to move tokens should complete transfers by Sept. 15 or early on Sept. 16, while trading generally continues under each exchange's own policy. The suspensions do not change the status of the token itself.

Ordinary holders need to take no action. Interstellar changes neither VET nor VTHO tokenomics: supply, VTHO issuance and burning rules, staking rewards, validator and delegator allocations, StarGate NFTs, governance voting power, wallet addresses, and token contracts all stay as they are, according to VeChain. VTHO generation continues under the existing framework after the upgrade. The broader Interstellar program does not end with VIP-255. VeChain states that work on Ethereum transaction equivalence will be specified separately and was not part of the upgrade vote. For now, the activation tests whether infrastructure providers, exchanges, developers, and holders can coordinate a consensus change while keeping applications running. Exchanges suspending transfers do so to manage the transition and shield users from network inconsistencies during the switch, which the reporting describes as temporary. The hardfork activates at block 25,902,540 on Sept. 16.
