## Repair

- Untracked image-only outputs in the news namespace now go to the same content-addressed pending archive as unfinished drafts. Exact bytes and hashes are retained, with `approved: false`, `mustReview: true`, and an explicit orphan-image marker. Unknown ownership remains unknown. They never enter the publication file list.
- Ready article image references, tracked/baseline/published assets, ignored files, symlinks, hard links and unsafe recovery paths retain their blocking checks.
- `news-research.mjs checkpoint` records candidate/slug ownership and completed source checks before image work or drafting. It leaves the candidate unreviewed, cannot count as ready, and cannot steal another candidate's slug.
- Same-day restoration recognizes unfinished checkpoints and restores them only for fresh review. Assignments prioritize checkpointed work, and repair prompts point to retained drafts rather than starting over.
- The workflow snapshots safe unpublished outputs independently of the publication validator, before uploading the recovery artifact. Thus a later validation failure does not itself discard draft files. Writer shutdown must be confirmed first.

Regression coverage reproduces both October 23 orphan filenames, with and without a ready article. It checks exact-byte retention, rerun behavior, genuine-audit requirements, unfinished checkpoint restoration, protected-file barriers and writer shutdown. This removes the observed deterministic failure; source outages, model failures and genuine editorial failures still remain visible rather than being labeled successful publication.
